\begin{abstract}
\todo{$\le$150 words, one sentence per slot:}
\todo{(1) Coding agents produce working code and decaying architecture; nothing
guards architecture while code is being written.}
\todo{(2) \arcade{} is an installable library and MCP server that puts architecture
recovery, smell detection, decay metrics, and conformance checking inside the
agent's loop.}
\todo{(3) Mechanism: 19 MCP tools over 7 language parsers and 5 recovery
algorithms, with per-call token budgeting and session handles so an agent can
afford to call them.}
\todo{(4) The guardrail is proactive -- it answers where code should live and
what it may depend on before the code exists.}
\todo{(5) Evidence: on greenfield tasks an unaided agent introduced a forbidden
dependency in 3 of 14 runs; with the guardrail, 0 of 14, with no false positives.}
\todo{(6) Availability: pip, MIT, public repo.}

\subsection{Parsing}
\todo{tree-sitter; one \tool{LanguageParser} per language behind a
\tool{@register\_parser} registry. Seven languages: Java and Python always
available, C, TypeScript, Go, Kotlin, and Rust via the \tool{[languages]} extra.
Polyglot merge relinks imports and inheritance across FQN space.}

\todo{LIMIT -- state it here, in the body, not in a footnote: relinking is
family-scoped, and the JVM family (Java/Kotlin) is the only validated pair.
Every other language is its own family and merges without cross-language edges.
Overclaiming general cross-language recovery is a cheap reject.}

\subsection{Recovery}
\todo{Five algorithms: \tool{pkg} (default, deterministic), \tool{wca},
\tool{acdc}, and the LLM-powered \tool{arc} and \tool{limbo}. Explain why the
guardrail path uses only deterministic glob/package mapping: the same code must
yield the same verdict every time, and it must be fast enough to call dozens of
times per session. This design rationale is the most defensible engineering
claim in the paper -- give it a real sentence, not a clause.}

\subsection{Delivery to the agent}
\todo{This subsection is what reviewers should remember. Do not let it get cut.}

\paragraph*{Session handles}
\todo{Tools return a compact summary plus a \tool{session\_id}; the agent calls
\tool{get\_full\_result} only when it actually needs the graph. Stored types:
\tool{IngestedRepo}, \tool{DependencyGraph}, \tool{Architecture},
\tool{SmellList}, \tool{MetricList}. Sessions are in-process and do not survive
a server restart -- say so, it belongs in Sec.~\ref{sec:conclusion} too.}

\paragraph*{Token budgeting}
\todo{Every tool accepts \tool{max\_tokens}. Two strategies:
\tool{truncate\_result} applies seven ordered levels of domain-aware reduction
to graph/architecture payloads (truncate component entity lists $\rightarrow$
collapse entities to an FQN$\rightarrow$kind map $\rightarrow$ collapse edges to
relation counts $\rightarrow$ drop edges $\rightarrow$ drop entities $\rightarrow$
minimize components $\rightarrow$ drop packages), stopping as soon as the budget
is met; \tool{enforce\_budget} drops the largest top-level key repeatedly for
everything else, flagging \tool{\_budget\_truncated}. GIVE A CONCRETE
BEFORE/AFTER TOKEN COUNT on a real repo -- that single number is the most
quotable thing in the paper.}

\paragraph*{Caching}
\todo{\tool{DependencyGraph} cached to \tool{.arcade-cache/}, keyed on file
paths plus mtimes, auto-invalidated on change. One sentence; first on the cut
list.}

\subsection{Tiered enforcement}
\todo{The \arcguard{} layer enforces in two tiers. Advisory (MCP tools, plus a PostToolUse hook that injects findings into
the agent's context so agents that forget to ask still get nudged) escalating to
blocking (pre-commit hook, CI gate, \tool{--fail-on error} exits non-zero).}
